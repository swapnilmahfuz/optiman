# Fresh Optiman cPanel installation

Back up the existing site, database and uploads first. This package targets `/home/optiman1/optiman-private/` and `/home/optiman1/public_html/optiman-backend/`; it does not include root `public_html` files, `cgi-bin`, or `php.ini`. Remove only the old Optiman backend folders after confirming backups. Do not extract over an existing installation: doing so could overwrite its files or lock.

1. Create a **new empty** MariaDB/MySQL database and user in cPanel and assign ALL PRIVILEGES on that database. Do not delete existing databases. Note the full cPanel-prefixed names.
2. Upload the ZIP to `/home/optiman1/` and extract once there. Check `optiman-private` is outside `public_html`. Keep private folder permissions 0700 or 0750 where supported; public directories 0755 and public files 0644 are typical. Never use 0777. The PHP account must be able to write the private folder and `public_html/optiman-backend/uploads/products`.
3. Using a trusted password manager, generate a **unique random 64-character lowercase hexadecimal token** (256 bits). In cPanel File Manager create `/home/optiman1/optiman-private/setup.token`, edit it to contain only that token, and set permissions to 0600. Keep it private; do not put it in the ZIP, GitHub, chat, a URL, or public_html.
4. Open `https://optiman.bd/optiman-backend/install.php`. Enter the token, then the new database host, name, user and password and the first Owner name, email and password. Submit. HTTPS and a session CSRF token are required. Do not send credentials to anyone. The installer makes tables, creates the Owner, generates a random secret and writes the private config. It invalidates the token and locks itself. There is no default Owner password.
5. Sign in at `https://optiman.bd/optiman-backend/admin/`. Verify the API via `https://optiman.bd/optiman-backend/index.php?path=/api/v1/products`. Confirm HTTPS, PHP upload execution protection, image uploading, login/logout and access controls with test data. Only then consider real data.

The installer refuses existing config, a lock file, or a database containing tables or views. MariaDB DDL cannot roll back automatically. If setup fails after migration begins, the lock prevents retry: inspect server logs privately, restore/choose another **empty** database, remove only the failed installation files and lock after backup, and generate a new token. Never reuse a partially migrated database or delete an existing database automatically. Incorrect token attempts are limited globally to eight per 15 minutes.

The package uses Apache/LiteSpeed `.htaccess` to restrict executable uploads. If the host ignores or forbids these directives, obtain equivalent host configuration and verify before use. PHP/server errors must be logged privately. This package was tested locally; actual cPanel permissions, HTTPS, server rules and backups require verification on the host.
